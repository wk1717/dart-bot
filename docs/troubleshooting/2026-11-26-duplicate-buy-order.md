# 재실행 때 같은 종목을 두 번 살 수 있음

- 발생: 2026-11-26 (코드 점검으로 발견, 운영에서 실제로 터진 적은 없음)
- 관련: `trader.py` `buy()`, `reconcile()`, Supabase `trades`, KIS 주문 API, 08:40·09:05 매수 실행
- 상태: 수정 완료 (ce90008), 실계좌 대사 1회 일치 확인

## 증상

실제로 겪진 않음. 매수는 08:40에 돌고, 거절된 주문을 다시 사려고 09:05에 한 번 더 돎. 09:05 실행은 "`trades`에 있으면 이미 산 것"으로 판단함.

## 원인

매수 순서가 "주문 → 장부(`trades`) 쓰기"였음.

```python
try:
    odno = order("buy", r["stock_code"], qty)
except Exception as e:  # 주문 실패는 기록 안 함 → 휴장일이면 다음 거래일에 다시 시도
    continue
bot.sb("POST", "trades", {...})
```

두 경우에 장부에 안 남고 주문만 나감.

1. 주문은 나갔는데 Supabase 쓰기가 실패
2. KIS 응답이 타임아웃·5xx로 왔는데 실제로는 주문이 접수됨. 코드는 "실패"로 보고 기록 안 함

그러면 09:05 실행이 같은 종목을 또 삼. 그리고 장부와 실제 계좌가 어긋나도 알아챌 방법이 없었음.

## 해결

**장부 먼저 쓰고 주문**

```python
bot.sb("POST", "trades", {...})        # 실패하면 주문 안 냄
try:
    odno = order("buy", code, qty)
except Rejected:                        # KIS가 rt_cd로 거절 = 확실히 안 나감 → 장부에서 지움
    bot.sb("DELETE", key)
except Exception:                       # 타임아웃·5xx = 나갔는지 모름 → 장부에 남김
    lines.append("확인 필요 ○○: 주문 결과 모름")
bot.sb("PATCH", key, {"buy_odno": odno})
```

- 실패를 "확실히 안 나감"과 "모름"으로 나눔. `kis()`가 `rt_cd != 0`이면 `Rejected`를 던짐
- "모름"은 장부에 남아서 재실행이 다시 안 삼. 실제로 체결됐으면 `fill_buy_prices()`가 매수가를 채움
- 장부엔 없는데 계좌에 이미 있는 종목도 안 삼
- 체결 매칭 키를 주문번호에서 접수번호로 바꿈. 주문번호가 없는 "모름" 거래도 정산되게

**장부 대사**

정산(15:40) 끝에 `reconcile()`이 장부 보유 종목·수량과 KIS 잔고를 비교함. 어긋나면 텔레그램:

```
⚠️ 모의투자 대사 불일치
엑셈(205100) 장부 210주 · 계좌 0주
```

## 수치

| | before | after |
|---|---|---|
| 주문 뒤 장부 쓰기 실패 시 09:05 재실행 | 같은 종목 다시 주문 | 주문 안 함 (장부에 이미 있음) |
| 장부-계좌 불일치 감지 | 방법 없음 | 정산 때마다 비교 |
| 실계좌 대사 (11/26) | - | 4종목 일치 (`python3 trader.py reconcile` → "대사 일치: 4종목") |

## 재발 방지

`TraderLedgerTest` 6개

- 장부 POST가 주문 앞에 오는지
- `Rejected`면 장부에서 지우는지
- 타임아웃이면 장부에 남기고 "확인 필요"를 띄우는지
- 계좌에 이미 있으면 주문 안 내는지
- 장부 쓰기가 실패하면 주문 안 내는지
- 대사가 어긋난 종목만 알리고, 맞으면 조용한지

매도 쪽은 안 바꿈. 하루 한 번만 돌고, 같은 수량을 또 팔면 KIS가 주문가능수량 초과로 거절할 것으로 봄 (확인 안 함).
